# Two deployment images (frontend nginx + backend jar) instead of one combined image

We deploy as two Docker images — a Spring Boot API jar and an nginx image that serves the built React SPA and proxies API calls to the backend — orchestrated by a root `docker-compose.yml`. The API has no `/api` prefix, so root-level paths like `/admin/event-types` collide with SPA routes; we rejected a single-process image (Spring serving the SPA alongside JSON) to keep the frontend and backend independently deployable, and we rejected moving the API under `/api` in `main.tsp` because that changes the public contract the automated checks depend on. The remaining three colliding admin GETs are disambiguated in nginx by `Accept` header (`text/html` → SPA shell, otherwise → proxy). The frontend calls the API same-origin (`VITE_API_BASE_URL=''`), nginx listens on `PORT`, and the backend binds `server.port=${PORT:8080}`.
